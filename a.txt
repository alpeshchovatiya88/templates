SMI3.0 is implemented as a mortgage-insurance risk modelling framework that combines policy and borrower preprocessing, binary risk prediction, an external LGD dependency, loss calculations, model evaluation and SageMaker model registration. The supplied training code uses Snowflake and S3 inputs, AWS SageMaker for orchestration, and MLflow for experiment and artifact tracking.

The configured training implementation is an XGBoost classifier within a scikit-learn preprocessing pipeline. Although the supplied Docker notebook installs AutoGluon, the reviewed train.py uses XGBClassifier directly. Its configuration specifies five-fold stratified cross-validation, out-of-fold predictions, a subsequent fit on the full training population, and ROC AUC as the evaluation metric. This should not be described as AutoGluon bagging without evidence from a different executed implementation.

The technical validation objective is to determine whether the implementation is technically sound, reproducible, appropriately controlled, consistent with the approved model design, and suitable for independent replication. The review covers data processing, feature engineering, target construction, model methodology, diagnostics, explainability, MLOps and governance.

Conclusions in this review are separated into code-evidenced observations and procedures requiring execution. Source code can show that a calculation or control was written, but cannot establish that it ran successfully on the approved dataset or that the resulting model meets acceptance criteria. The supplied archive also contains syntax and import inconsistencies; an executable version of the source and its dependencies is required before independent replication can be completed.

SMI3.0.5 Key Design and Updates

• Automated policy and borrower preprocessing, followed by application-level merging.
• Snowflake policy and borrower source data; S3 economic, claim and delinquency, geography, credit-score and other static inputs.
• Application-level borrower aggregation using multiple summary statistics and credit-score source selection logic.
• Binary target derived from mortgage status, claim and 90-day delinquency categories; declined applications assigned target=1 in the reviewed code.
• Funded-mortgage training population with BOOKYEAR 2009–2015; later test population with EFFECT_SID 202101–202312.
• Separate recent population with EFFECT_SID 202510–202605 and a specified credit-score source.
• HPI and unemployment feature construction using historical and future economic inputs; reference-period values and a fixed contract rate applied in test and recent processing.
• External LGD artifact used in downstream loss and loss-ratio calculations.
• XGBClassifier within a scikit-learn preprocessing pipeline; ROC AUC as the configured evaluation metric.
• Five-fold stratified cross-validation, out-of-fold predictions and a subsequent full-training fit; optional grid search disabled in the supplied configuration.
• Training outputs covering model artifacts, predictions, classification metrics, feature importance and optional SHAP explanations.
• Evaluation outputs covering test and recent predictions, AUC where labels are available, model metadata, risk ranking and related diagnostic artifacts.
• SageMaker preprocessing, profiling, training, evaluation and model-registration steps; registration defaulting to PendingManualApproval.
• Data-quality ConditionStep defined in code but absent from the active pipeline step list; no evidenced evaluation-threshold gate before registration.
• MLflow experiment and artifact tracking, with model-package metadata linking to the experiment and available source-control information.

Technical Validation Scope

In scope: code review and independent procedures

• Trace Snowflake and S3 inputs through joins, deduplication, missing-value handling, application-level aggregation and final train, test and recent extracts.
• Reconcile population counts and selection criteria, including funded status, book-year and effective-period filters, product filters, score-source selection and exclusions at every stage.
• Reconstruct event categories and the binary target from source indicators. Investigate the treatment of declined applications, missing outcomes, observation windows and outcome maturity before relying on test AUC.
• Review feature transformations, credit-score logic, economic features, fixed values, LGD integration and the availability of each feature at the intended prediction time.
• Reperform feature-exclusion and leakage checks, including identifier, status, outcome and post-decision fields.
• Independently reproduce preprocessing, the five-fold out-of-fold procedure, full-data fit, model serialization and test-set scoring using the approved executable code, configuration, data snapshot and image.
• Recompute discrimination, calibration and threshold-dependent metrics on an eligible independent test population; assess results by time period, geography, product and other material segments with adequate sample sizes.
• Review feature importance and SHAP calculations for model-input consistency, reference population, sampling and interpretation. Execute stability, sensitivity and drift tests on appropriate development, test and recent populations.
• Trace MLflow runs and artifacts to dataset versions, configuration, code commit, fitted model hash, evaluation output and registered model package.
• Verify the SageMaker pipeline graph and observe whether quality checks, validation results and approval conditions operate as intended. Resolve the difference between code comments and the active step list.
• Compare batch and real-time predictions on identical representative inputs once the deployment source, image and test evidence are supplied.
• Record code-evidenced findings separately from executed test results, limitations, remediation and validator conclusions.

Out of scope for this source-code review

• Certification of the accuracy or completeness of Snowflake, S3 and external source-system data without source-to-target reconciliation evidence.
• Validation of the external LGD model methodology without its documentation, artifact and separate validation evidence.
• Business approval of target semantics, population selection, cut-offs, economic assumptions and product treatment.
• Final privacy, legal, ethical, fairness and third-party data-use conclusions.
• Final performance, calibration, stability and fitness-for-use conclusions before independent tests are run on the approved data and model artifact.
• Conclusions on production monitoring effectiveness without monitoring configuration, operating evidence and observed results.
• Final model risk rating and residual-risk acceptance.
